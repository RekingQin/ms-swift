## 1. 总体框架

ms-swift 的顶层设计是 **"CLI 薄壳 → Pipeline 导演 → Trainer 执行"** 三层结构，底层复用 HuggingFace `Trainer` 体系并深度魔改：

```text
用户命令（swift sft --model Qwen3-8B --dataset ...）
    ↓
swift/cli/main.py (ROUTE_MAPPING 分发)
    ↓
swift/cli/sft.py (单卡模式 / unsloth / Ray 初始化)
    ↓
swift/pipelines/train/sft.py (SwiftSft.run)
    ├─ 参数解析 (BaseArguments / SftArguments)
    ├─ 模型加载 (args.get_model_processor)
    ├─ 模板准备 (args.get_template)
    ├─ 数据准备 (_prepare_dataset)
    ├─ 打适配器 (TunerMixin.prepare_model)
    ├─ 构造 Trainer (TrainerFactory.get_trainer_cls)
    └─ trainer.train(resume_checkpoint)
    ↓
swift/trainers/seq2seq_trainer.py (training_step → compute_loss)
    ↓
swift/trainers/mixin.py (SwiftMixin._save / _save_flash_checkpoint)
```

## 2. 入口层：`swift/cli/`

### 2.1 子命令分发（`swift/cli/main.py`）

`ROUTE_MAPPING`（L14-27）把子命令字符串映射到模块路径：

```python
ROUTE_MAPPING: Dict[str, str] = {
    'pt': 'swift.cli.pt',
    'sft': 'swift.cli.sft',
    'infer': 'swift.cli.infer',
    'merge-lora': 'swift.cli.merge_lora',
    'web-ui': 'swift.cli.web_ui',
    'deploy': 'swift.cli.deploy',
    'rollout': 'swift.cli.rollout',
    'rlhf': 'swift.cli.rlhf',
    'sample': 'swift.cli.sample',
    'export': 'swift.cli.export',
    'eval': 'swift.cli.eval',
    'app': 'swift.cli.app',
}
```

`cli_main()`（L86）的核心逻辑：

1. 取 `sys.argv[1]` 作为子命令名，`replace('_', '-')` 规范化；
2. `parse_yaml_args(argv)` 支持 `--config xxx.yaml` 展开配置；
3. **关键**：若设置了 `NPROC_PER_NODE` / `NNODES` 环境变量，且命令在 `{'pt', 'sft', 'rlhf', 'infer'}` 中，则用 `torch.distributed.run` 多进程启动（`torchrun`），否则单进程 `python file_path`。

```python
torchrun_args = get_torchrun_args()
...
args = [python_cmd, '-m', 'torch.distributed.run', *torchrun_args, file_path, *argv]
result = subprocess.run(args)
```

### 2.2 子命令薄壳的初始化（以 `swift/cli/sft.py` 为例）

```python
if __name__ == '__main__':
    from swift.cli.utils import try_use_single_device_mode
    try_use_single_device_mode()      # SWIFT_SINGLE_DEVICE_MODE 单卡调试
    try_init_unsloth()                 # --tuner_backend unsloth 时配置环境
    from swift.ray_utils import try_init_ray
    try_init_ray()                     # Ray 初始化（可选）
    from swift.pipelines import sft_main
    sft_main()
```

其他子命令类似，最终都调用 `swift.pipelines` 中的 `xxx_main()`。

## 3. Pipeline 层：`swift/pipelines/`

### 3.1 基类 `SwiftPipeline`（`swift/pipelines/base.py`）

```python
class SwiftPipeline(ABC, ProcessorMixin):
    args_class = BaseArguments

    def __init__(self, args=None):
        self.args = self._parse_args(args)   # 参数解析
        self._set_seed()                      # seed = args.seed + rank
        self._compat_dsw_gradio(args)

    def main(self):                           # L49
        result = self.run()
        return result
```

- `_parse_args`（L31）：`parse_args(self.args_class, args)`，支持 `ignore_args_error`（未知参数忽略）。
- `_set_seed`（L24）：`seed_everything(args.seed + rank)`。
- 所有子 pipeline 实现抽象方法 `run()`。

### 3.2 训练 Pipeline 继承关系

```text
SwiftPipeline (base.py L14)
   └── SwiftSft (train/sft.py L22)            # SFT / PT 的基座
          ├── SwiftPretrain (train/pretrain.py L11)   # 仅换参数类
          └── SwiftRLHF (train/rlhf.py L23)           # 多模型 + RL trainer
```

### 3.3 `SwiftSft` 的完整 `run()` 流程（核心）

`swift/pipelines/train/sft.py`：

```text
SwiftSft.__init__ (L26)
  ├─ _prepare_model_tokenizer (L48)   # args.get_model_processor() 加载模型
  ├─ _prepare_template (L64)          # args.get_template() + set_mode('train')
  └─ _prepare_flash_ckpt              # Flash checkpoint 初始化

SwiftSft.run (L159)
  ├─ _prepare_dataset (L96)           # _get_dataset → _encode_dataset → _post_process_datasets
  ├─ prepare_model (TunerMixin L340)  # 打 LoRA/全参等适配器
  ├─ trainer_cls = TrainerFactory.get_trainer_cls(args)
  ├─ trainer = trainer_cls(...)       # 构造
  └─ self.train(trainer) (L254)
       ├─ _get_resume_checkpoint (L233)
       └─ trainer.train(resume_checkpoint)
```

**数据准备链**（`_prepare_dataset`）：

```text
_get_dataset
  → args.get_dataset() 内部走 swift/dataset/loader.py 的 load_dataset
  → 依据 dataset 语法 (dataset:subset#sample) 加载多个数据集并 concat/interleave/shuffle
_encode_dataset
  → RowPreprocessor / MessagesPreprocessor 预处理行
  → template.encode 编码成 input_ids/labels
_post_process_datasets (L125)
  → 非流式: 包 LazyLLMDataset（惰性编码，跳过坏样本）
  → 打包: PackingDataset / IterablePackingDataset
  → 纯流式: EncodePreprocessor 即时编码
```

## 4. Trainer 层：`swift/trainers/`

### 4.1 训练器选择：`TrainerFactory`（`swift/trainers/trainer_factory.py`）

```python
TRAINER_MAPPING = {                       # L13
    'causal_lm': Seq2SeqTrainer,
    'seq_cls': Trainer,
    'embedding': EmbeddingTrainer,
    'reranker': RerankerTrainer,
    'generative_reranker': RerankerTrainer,
    # rlhf_type → swift.rlhf_trainers.*Trainer
    'dpo': ..., 'orpo': ..., 'kto': ..., 'cpo': ...,
    'rm': ..., 'ppo': ..., 'grpo': ..., 'gkd': ...,
}
```

- `get_trainer_cls`（L57）：有 `rlhf_type` 用它，否则用 `task_type`。
- `get_training_args`（L61）：从 dataclass 过滤出训练参数。

### 4.2 `Seq2SeqTrainer` 训练循环（`swift/trainers/seq2seq_trainer.py`）

类定义：`Seq2SeqTrainer(SwiftMixin, DataLoaderMixin, HfSeq2SeqTrainer)`（L26）。

关键重写方法：

| 方法 | 行号 | 作用 |
|------|------|------|
| `_predict_data_collator` | L39 | 预测时把 batch 包成 `{'_data': batch}` |
| `evaluate` | L58 | predict_with_generate 时临时关 packing/padding_free |
| `prediction_step` | L65 | generate 分支用 infer_engine 推理并写 predict.jsonl |
| `_prepare_inputs` | L101 | SP prepare_inputs、logits_to_keep、MoE router_aux_loss_coef、注入 compute_loss_func |
| `compute_loss` | L125 | **核心**：调 `template.compute_sft_loss`；DFT/channel/loss_scale 用 `per_token_loss_func(_sp)` |
| `training_step` | L231 | 包 `template.forward_context` 再调 super |

**compute_loss 的数据流**：

```text
HF Trainer.training_step
    ↓
Seq2SeqTrainer.training_step (L231, 包 forward_context)
    ↓
Seq2SeqTrainer.compute_loss (L125)
    ├─ template.compute_sft_loss(...)   # 常规 SFT 交叉熵
    ├─ per_token_loss_func (L174, trainers/utils.py)     # 非 SP 逐 token CE + DFT
    └─ per_token_loss_func_sp (L142)                     # SP 分块 CE + GatherLoss
    ↓
返回 loss 标量 → backward
```

### 4.3 `Trainer`（`swift/trainers/trainer.py`）

`Trainer(SwiftMixin, DataLoaderMixin, HfTrainer)`（L17），用于 seq_cls/embedding/reranker：

- `_patch_loss_function`（L37）：兼容 PeftModel，包一层 loss_function 修 device_map；
- `train`（L62）：用 `_patch_loss_function` 包裹 `super().train`；
- `compute_loss`（L66）：调 super 计算并 `_compute_acc`，支持 `num_items_in_batch` 除梯度累积。

### 4.4 `SwiftMixin` 提供的核心能力（`swift/trainers/mixin.py`）

| 能力 | 方法 | 行号 |
|------|------|------|
| 初始模型保存（pissa/olora/lora-ga） | `_save_initial_model` | L224 |
| 模型保存（分 SwiftModel/Peft/原生） | `_save_model` | L322 |
| 整体保存（+ args.json + predict.jsonl） | `_save` | L416 |
| flash checkpoint 异步保存 | `_save_flash_checkpoint` | L598 |
| checkpoint 轮换删除 | `_rotate_flash_checkpoints` | L447 |
| resume 点查找 | `get_resume_checkpoint` | L521 |
| elastic 恢复点查找 | `get_resume_checkpoint_until_find_ucp` | L545 |
| 梯度检查点准备 | `_prepare_gradient_checkpointing` | L930 |
| 多模态 forward hook | `_patch_tasks` | L752 |
| 指标计算 | `_compute_acc` | L1104 |

### 4.5 `patcher.py`：对 transformers 的 monkey-patch

`swift/trainers/patcher.py` 安装三个回调 patch（L106-108）：

- `ProgressCallbackNew`（L33）：把训练进度写 `logging.jsonl`，加训练速度/内存统计；
- `DefaultFlowCallbackNew`（L61）：在 `max_steps` 时强制 evaluate/save；`max_epochs` 达界停训并保存；
- `PrinterCallbackNew`（L87）：on_log 写 jsonl 并打印。

**原因**：接管日志落盘与训练终止/保存时机，保证与 ms-swift 的 `logging.jsonl`/checkpoint 机制一致。

## 5. 三大训练入口差异：PT / SFT / RLHF

| 维度 | PT（预训练） | SFT（指令微调） | RLHF（人类对齐） |
|------|-------------|----------------|-----------------|
| CLI | `swift pt` | `swift sft` | `swift rlhf` |
| Pipeline | `SwiftPretrain`（继承 SwiftSft） | `SwiftSft` | `SwiftRLHF`（继承 SwiftSft） |
| 参数类 | `PretrainArguments` | `SftArguments` | `RLHFArguments` |
| 模型 | 单模型 | 单模型 | 多模型（ref/reward/value/teacher） |
| trainer | `Seq2SeqTrainer`（task_type=causal_lm） | 同左 | `rlhf_type` 决定（DPO/ORPO/KTO/CPO/RM/PPO/GRPO/GKD） |
| 数据 | 支持 `truncation_strategy='split'` | 标准 Lazy/Packing/Encode | KTO 特殊预处理；GRPO/GKD 用 cached dataset 延迟编码 |

### 5.1 `SwiftRLHF` 的特殊之处（`swift/pipelines/train/rlhf.py`）

- `_prepare_model_tokenizer`（L117）：额外加载 ref / reward / value / teacher 多个模型：
  - PPO 加载 value model；
  - GKD/GRPO 加载 teacher model（OPD-RL 场景）；
  - GKD 跳过 ref model。
- `_get_trainer_kwargs`（L226）：把 ref/reward/value/teacher_model、reward_template、vllm_client、reward_funcs、gkd_logits_topk 传给 trainer。

## 6. 推理 / 评测 / 部署 / 导出流程

### 6.1 推理 `SwiftInfer`（`swift/pipelines/infer/infer.py`）

```text
SwiftInfer.run (L95)
  ├─ 加载数据（cached 或 load_dataset）
  └─ infer_dataset() / infer_cli()
       └─ 用 InferEngine（transformers / vllm / sglang / lmdeploy）批量推理
       └─ 结果写 result_path（JSONL）
```

### 6.2 部署 `SwiftDeploy`（`swift/pipelines/infer/deploy.py`）

- `SwiftDeploy(SwiftInfer)`（L28），`run`（L237）注册 FastAPI 路由（`/chat/completions`、`/embeddings` 等）后用 uvicorn 起服务。

### 6.3 RL rollout server `SwiftRolloutDeploy`（`swift/pipelines/infer/rollout.py`）

- `SwiftRolloutDeploy`（L724），`run`（L1073）：RL 场景的 vLLM rollout server，FastAPI 暴露 weight 更新/infer 等路由，起多 DP worker。

### 6.4 评测 `SwiftEval`（`swift/pipelines/eval/eval.py`）

- `run`（L22）：先 `run_deploy` 起服务，再按 `eval_backend`（native/opencompass/vlmeval）构 TaskConfig 用 evalscope 评估。

### 6.5 导出 `SwiftExport`（`swift/pipelines/export/export.py`）

- `run`（L20）：按需 merge_lora、量化、ollama、cached_dataset、mcore/hf 转换、push_to_hub。

### 6.6 采样 `SwiftSampling`（`swift/pipelines/sampling/sampling.py`）

- `run`（L50）：按 `sampler_type`（Vanilla/Distill）分片采样生成数据，支持断点续采。

## 7. 训练循环内部：一个 step 发生了什么

以 SFT 为例（HF Trainer 标准循环 + ms-swift 扩展）：

```text
trainer.train()
  ├─ 每 step:
  │    ├─ get_train_dataloader (DataLoaderShard)
  │    ├─ _prepare_inputs (L101, seq2seq_trainer.py)
  │    ├─ template.forward_context (forward_context 管理 SP / grad ckpt)
  │    ├─ training_step (L231)
  │    │    ├─ compute_loss (L125 → template.compute_sft_loss)
  │    │    ├─ accelerator.backward(loss)
  │    │    └─ optimizer.step() / lr_scheduler.step()
  │    ├─ logging (ProgressCallbackNew → logging.jsonl + wandb/tensorboard)
  │    ├─ evaluation (evaluate → metrics/ 计算)
  │    └─ save (SwiftMixin._save → checkpoint-{step})
  └─ 结束: _save_trainer_state
```

### 7.1 指标上报路径

```text
trainer._log (HF) 
    ↓
ProgressCallbackNew.on_log (patcher.py L51)
    ├─ 主进程写 {output_dir}/logging.jsonl
    └─ 注入 global_step/max_steps/elapsed_time/remaining_time/train_speed
    ↓
report_to=tensorboard/wandb/swanlab → tb_utils / wandb.log / swanlab.log
```

### 7.2 评估路径

```text
trainer.evaluate
    ↓
metrics/eval_metrics_map (swift/metrics/mapping.py L10)
    └─ acc / nlg / infonce / paired / reranker
    ↓
Seq2SeqTrainer.evaluate (L58, predict_with_generate 时走 infer_engine)
```

## 8. 关键调用链速查表

| 场景 | 调用链 |
|------|--------|
| 参数解析 | `SwiftPipeline.__init__._parse_args` → `parse_args`（swift/utils 或 arguments） |
| 模型加载 | `args.get_model_processor()` → `swift/model/register.py:get_model_processor`（L516）→ `ModelLoader.load` |
| 模板 | `args.get_template()` → `swift/template/register.py:get_template`（L55） |
| 数据集 | `args.get_dataset()` → `swift/dataset/loader.py:load_dataset`（L224） |
| 适配器 | `TunerMixin.prepare_model`（tuner.py L340）→ `Swift.prepare_model`（tuners/base.py L703） |
| 训练器选择 | `TrainerFactory.get_trainer_cls`（trainer_factory.py L57） |
| 训练 | `SwiftMixin.train`（mixin.py L961）→ `super().train` |
| 保存 | `SwiftMixin._save`（L416）→ `_save_model`（L322） |
| 恢复 | `SwiftSft._get_resume_checkpoint`（sft.py L233）→ `trainer.get_resume_checkpoint`（mixin.py L521） |

## 9. 总结：一句话主线

```text
swift <子命令>  →  cli 薄壳  →  Pipeline.run  →  Trainer.train  →  compute_loss  →  backward/optimizer  →  _save
```

其中 Pipeline 负责"组装"，Trainer 负责"执行"，compute_loss 是训练的灵魂（SFT 走 template 的 SFT loss，RLHF 走各自 trainer 的 loss）。
