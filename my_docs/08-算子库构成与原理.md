## 1. 算子来源总览

```text
自研算子（swift/ 内）:
  ├─ 序列并行: Ulysses all-to-all / Ring-Attention kernel / GatherLoss / ChunkedCrossEntropy
  ├─ loss_scale: 上下文损失权重（非 GPU kernel，而是数据层逻辑）
  ├─ tuners: MergedLinear（QKV 合并）、bnb 量化 LoRA dispatcher
  └─ optimizers: GaLoreProjector（SVD 投影）、MuonClip 的 max-logits tracker

外部算子库（条件依赖）:
  ├─ flash-attn 2/3     # 注意力 kernel
  ├─ liger-kernel       # 融合 loss（LigerFusedLinearGRPOLoss / JSDLoss）
  ├─ unsloth            # 训练加速
  ├─ apex / triton      # 混合精度 / 自定义 kernel
  └─ Megatron-Core      # 分布式算子（TP/PP/EP）
```

## 2. 序列并行算子（`swift/sequence_parallel/`）

### 2.1 总控 `SequenceParallel`（`sequence_parallel.py` L64）

单例 `sequence_parallel`（L723），负责：

- `prepare`（L334）：初始化 device mesh 与 flash-attn patch；
- `_init_device_mesh`（L635）：通过 GCD（最大公约数）切分 SP/RP 维度；
- `pad`（L377）/ `split`（L492）/ `gather`（L415）：zigzag 切分聚合；
- `pad_and_split_inputs`（L537）：统一 pad + split；
- `prepare_inputs`（L702）。

### 2.2 Ulysses 注意力（`ulysses.py`）

`DistributedAttention`（L95）：

```text
原理: 把 sequence 维度切到不同 rank，每 rank 拥有部分 seq + 全部 head，
      通过 all-to-all 交换为"全部 seq + 部分 head"，再做标准注意力。

single_all_to_all (L56) / _SeqAllToAll (L74):
  基于 dist.all_to_all_single
  scatter_idx / gather_idx 控制交换方向
  backward 时交换反向 index（保证梯度正确）
```

限制（v4.0 早期）：要求 `seq_len % SP == 0` 且 `num_heads % SP == 0`。README 说明 Ulysses 现已支持与 ring-attention 结合，输入序列可切任意块数（不再受限于 num_heads）。

### 2.3 Ring-Attention（`zigzag_ring_attn.py`）

```text
原理: 序列按 zigzag 方式切分到各 rank（rank i 分得块 i 和 (2P-1-i)），
      每 rank 算局部注意力，KV 沿环轮转（RingComm），
      用 online softmax（lse 拆分）合并结果，得到与全注意力等价的输出。
```

关键实现：

- `zigzag_ring_flash_attn_varlen_func`（L682）：**变长 flash-attn kernel**，直接调用 `flash_attn` 的 varlen 接口，拆 lse/out 做 online softmax 融合；
- `update_out_and_lse`（L69）：在线 softmax 合并；
- `ring_utils.py` `RingComm`（L8）：`isend/irecv + batch_isend_irecv` 实现 KV 轮转（通信算子）；
- `zigzag_ring_attn_npu.py`：NPU 版（`npu_forward`/`npu_backward`）。

### 2.4 梯度聚合算子（`utils.py`）

- `GatherTensor`（L13）：可导的 gather；
- `GatherLoss`（L30）：loss 的 gather 聚合（SP 下各 rank 的 loss 片段汇总）；
- `ChunkedCrossEntropyLoss`（L65）：**分块交叉熵**，避免整大矩阵，省显存；
- `SequenceParallelSampler`（L107）/ `SequenceParallelDispatcher`（L152）：SP 数据分发（配合 `get_packed_seq_params`）。

## 3. loss_scale（`swift/loss_scale/`）

> 注意：这里的"算子"是**数据/模板层的损失权重控制逻辑**，不是 GPU kernel。

### 3.1 原理

Agent 训练中，一条消息的 token 重要性不同（如工具调用部分 vs 推理部分），`loss_scale` 给每个 token 一个 [0,1] 权重。

```text
LossScale (base.py L12)
  base_strategy: default / last_round / all
  ConfigLossScale (L139): 从 JSON 加载 token→权重映射
  ConcatLossScale (L202): 多策略权重相乘组合
  agent.py: REACT / Qwen / Hermes / AgentFlan / AlphaUmi 策略
  calculate_loss_scale (utils.py L7): 按 Agent 响应分段计算权重（arXiv:2309.00986）
```

### 3.2 与 liger / 显存的结合

`swift/template/base.py` `_encode_context_list`（L1089-1113）：

```text
is_binary_loss_scale=True 时:
  把 loss_scale 折叠进 labels（权重 0 处置 -100）
  → 兼容 liger_kernel 融合 loss
  → 省显存（不用额外保存 loss_scale 张量）
非 binary 时: 额外保存 loss_scale 张量
```

## 4. 融合损失算子（liger-kernel 集成）

### 4.1 GRPO 融合损失

`grpo_trainer.py` `_prepare_liger_loss`（L2059）：

```python
from liger_kernel.chunked_loss import LigerFusedLinearGRPOLoss
# 把 linear + GRPO loss 融合成一个 kernel，前向一次拿到 loss，省 activation
```

`compute_liger_loss`（L1762）：融合线性 + GRPO 损失前向。

### 4.2 GKD 融合损失

`gkd_trainer.py` `use_liger_gkd_loss`（L146）：`LigerFusedLinearJSDLoss`。

### 4.3 SFT 融合

`swift/trainers/arguments.py` `_patch_liger_kernel`（L210）/ `_init_liger`（L223）：SFT 场景的 liger 集成。

### 4.4 兼容性校验

`trainers/arguments.py` L544-565：GRPO + liger 的版本/不支持特性断言。

## 5. Tuner 内核算子

### 5.1 MergedLinear（`swift/tuners/lora_layers.py` L540）

```text
QKV 合并投影: 把 Wq/Wk/Wv 合并成一个大矩阵，LoRA 只注入一次
→ 减少 kernel 调用，提速 + 省显存
```

### 5.2 bnb 量化 LoRA dispatcher

`dispatch_bnb_8bit`（lora_layers.py L91）等条件注册：对 bnb 8bit/4bit 量化层做 LoRA 注入的特殊处理。

## 6. 优化器算子（`swift/optimizers/`）

### 6.1 GaLoreProjector（`galore/galore_projector.py` L6）

```text
SVD 求正交投影矩阵 P
project (L16):   grad → P^T grad P（投影到低秩子空间）
project_back (L51): 低秩更新 → 投影回全秩
支持 std / left / right / full 投影
```

- `GaLoreAdamW`（adamw.py L140）：step 中先投影再更新再投影回；
- `GaLoreAdamW8bit`：bnb 8bit 版；
- `QGaLoreAdamW8bit`（utils.py L202）：Q-GaLore（量化梯度）。

### 6.2 MuonClip 的 max-logits 追踪（`muonclip.py` L15）

`_MaxLogitsTracker`：通过 patch `softmax` / `SDPA` / `flash_attn_func`（`enable_flash_attn` L123）估算每步 max logits，用于 MuonClip 的 clip 依据。

## 9. 算子性能对比要点

| 算子 | 省显存 | 提速 | 说明 |
|------|--------|------|------|
| Flash-Attn 2/3 | ✓ | ✓✓✓ | 标准选择 |
| liger 融合 loss | ✓✓ | ✓✓ | GRPO 免存全量 logits |
| Ring-Attention | ✓✓ | ~线性扩展 | 序列可无限长，通信多 |
| Ulysses | ✓ | ✓ | all-to-all 一次交换 |
| MergedLinear | ✓ | ✓✓ | QKV 合并注入 |
| GaLore | ✓✓（优化器状态） | — | 7B 可 9GB 训练 |
| ChunkedCrossEntropy | ✓ | — | 分块避免大矩阵 |
