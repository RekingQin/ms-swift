## 1. 算法总览

ms-swift 的优化算法分三层：

```text
第一层：rlhf_type（选 trainer）     dpo / orpo / simpo / kto / cpo / rm / ppo / grpo / gkd
第二层：GRPO 内的 loss_type 变体    grpo / dapo / bnpo / dr_grpo / fipo / cispo / sapo / real
第三层：advantage / 采样变体        rloo / reinforce_plus_plus / gdpo / 动态采样 / RLSD / SDAR / OPD-RL
```

| 算法 | 类型 | 实现位置 |
|------|------|----------|
| GRPO | 在线 RL | `grpo_trainer.py` loss_type='grpo' |
| DAPO | 在线 RL | loss_type='dapo' + 动态采样 |
| GSPO | 在线 RL | `importance_sampling_level`（sequence_token） |
| SAPO | 在线 RL | loss_type='sapo'（软门控） |
| CISPO | 在线 RL | loss_type='cispo'（上界裁剪） |
| CHORD | 在线 RL | `compute_chord_loss`（叠加 SFT） |
| RLOO / Reinforce++ | 在线 RL | `advantage_estimator` |
| FIPO | 在线 RL | loss_type='fipo'（Future-KL） |
| REAL | 在线 RL | loss_type='real'（正负组 logsumexp） |
| RLSD / SDAR / OPD-RL | 自蒸馏 RL | `apply_rlsd_reweight` / `compute_sdar_loss` / teacher 信号 |
| DPO / SimPO / CPO | 离线偏好 | `dpo_trainer.py` / `cpo_trainer.py` |
| KTO | 离线偏好 | `kto_trainer.py` |
| ORPO | 离线偏好 | `orpo_trainer.py` |
| RM | 奖励模型 | `reward_trainer.py` |
| GKD | 知识蒸馏 | `gkd_trainer.py` + `gkd_loss.py` |
| PPO | 在线 RL（经典） | `ppo_trainer.py` |

## 2. GRPO 训练器内部结构（`swift/rlhf_trainers/grpo_trainer.py`）

`GRPOTrainer(RolloutTrainerMixin, SwiftMixin, HFGRPOTrainer)`（L90），继承自 trl 的 GRPOTrainer 并深度魔改。

### 2.1 单次生成-训练循环

```text
dataloader 产出 generation batch
    ↓
_prepare_inputs (L189)
    ├─ 若 sequence_parallel: RepeatSampler (L176)
    ├─ _rollout_samples (L215)          # 样本化 + 生成 completions
    │    ├─ encode_sample
    │    └─ _generate_completions       # vLLM/SGLang 引擎
    ├─ _score_completions               # 奖励计算
    ├─ _compute_advantages              # advantage
    └─ 拆分成 per_device_train_batch_size 的 micro-batch，缓冲复用
    ↓
compute_loss (L862)
    └─ _compute_loss (L878) → _compute_loss_single / _compute_loss_chunked
        └─ _compute_loss_and_metrics (L948)    # 核心 loss
```

### 2.2 奖励计算（`swift/rl_core/grpo_algorithm.py`）

`compute_rewards_per_func`（L17）：

- 输入：`samples` + `reward_funcs` + `reward_model_plugins`；
- 输出：`[N, n_funcs]` 奖励矩阵；
- 支持：同步 callable、**异步 callable**（`_is_async_reward` L12 检测，`asyncio.gather` 并发）、**奖励模型**（nn.Module，走 plugin）；
- 所有奖励函数返回 None 时告警（L80-85）。

`score_completions`（L90）：`use_gym_env` 时把 gym 的 `total_reward` 作为附加奖励列拼接。

### 2.3 Advantage 计算（`swift/rl_core/advantage.py`）

`compute_advantages`（L10）纯张量函数：

```text
rewards = sum(rewards_per_func * reward_weights)      # [N]
若 kl_in_reward: rewards -= beta * kl_values           # KL 正则入 reward
grouped = rewards.view(-1, K)                          # K = num_generations

advantage_estimator:
  grpo:        adv = rewards - group_mean
  rloo:        adv = rewards*K/(K-1) - group_mean*K/(K-1)
  reinforce++: adv = rewards - group_mean, 再按 scale 归一化

scale_rewards:
  batch: std = rewards.std()
  group: std = grouped.std(dim=1)  repeat_interleave(K)
  gdpo:  每奖励函数独立 (r - mean)/std，再加权求和再标准化
  none:  不归一化

最终: adv = adv / (std + 1e-4)
```

`compute_advantages_dynamic`（L92）：按 `prompt_id`/`request_id` 分组（DAPO 动态采样场景，每组样本数可变）。

### 2.4 Per-token advantage 扩展（`expand_advantage_to_per_token` L253）

```text
per_token_adv = adv[B].unsqueeze(1).expand(B, T)
若 OPD-RL teacher 存在: per_token_adv += teacher_kl_coef * (teacher_logp_t - student_logp_t)
```

### 2.5 核心 loss：`_compute_loss_and_metrics`（L948）

```text
per_token_logps, entropies = 模型 forward (L953)
per_token_kl = exp(clamp(ref_logp - logp, -20, 20)) - ratio - 1   # KL penalty (L987-990)
log_ratio = per_token_logps - old_per_token_logps

importance_sampling_level (GSPO):
  token:         log_w = log_ratio
  sequence:      log_w = 序列平均 log_ratio
  sequence_token: log_w = logp - logp.detach() + seq_level  # GSPO-token

coef_1 = exp(log_w)

loss_type 分支 (L1050-1145):
  cispo:  -clamp(coef_1, max=eps_high) * adv * logp
  sapo:   -sigmoid(tau*(coef_1-1))*(4/tau) * adv   # 正负分开 tau
  real:   logsumexp 正/负组 loss (L1104-1135)
  grpo/bnpo/dr_grpo/dapo/fipo:  PPO clip: -min(coef_1*adv, clamp(coef_1,1-eps_low,1+eps_high)*adv)
      归一化差异:
        grpo/sapo:  序列均值
        bnpo:       总 token
        dr_grpo:    batch_size * max_completion_length
        cispo/dapo/fipo: 跨进程总 token (num_items_in_batch / num_processes)

可选附加:
  per_token_loss += beta * per_token_kl            # KL 惩罚 (L1077)
  entropy_mask (top_entropy_quantile 过滤)         # Entropy-Reg (L1075)
  rollout_is_weights (off-policy IS correction)    # L1080
  off_policy_sequence_mask                         # L1083-1094
  sdar_loss (SDAR 自蒸馏)                          # L1152-1159
  chord_loss (CHORD 叠加 SFT)                      # L1228
```

### 2.6 各 loss_type 归一化对照表

| loss_type | clip 方式 | 归一化 | 特点 |
|-----------|----------|--------|------|
| `grpo` | 标准 PPO 双 clip | 序列均值 | 基线 |
| `dapo` | 双 clip + `delta` 上界 | 跨进程总 token | 动态采样 |
| `bnpo` | 双 clip | 总 token | BNP 归一化 |
| `dr_grpo` | 双 clip | batch*max_len | Dr.GRPO |
| `fipo` | 双 clip + Future-KL 权重 | 跨进程总 token | token 级影响加权 |
| `cispo` | 仅上界 clip | 跨进程总 token | 防下溢 |
| `sapo` | sigmoid 软门控 | 序列均值 | 平滑门控 |
| `real` | 无 clip | 组内 logsumexp | 正负样本分离 |

## 3. DAPO 动态采样（`swift/rl_core/resample.py` + `grpo_trainer.py`）

DAPO 的四个核心组件在 ms-swift 中的实现：

1. **Clip-Higher**：`loss_type='dapo'` 时 `coef_1 = clamp(coef_1, max=delta)`（grpo_trainer L1067-1068）；
2. **动态采样**：`_dynamic_sampling`（grpo_trainer L644）+ `compute_std_for_dynamic_sampling`（grpo_algorithm.py L130）+ `compute_advantages_dynamic`（advantage.py L92）+ `_prepare_resample_data_iterator`（L2267）；
3. **超长过滤**：`overlong_filter`（truncated_mask 过滤，L979-984）；
4. **Token 级 loss**：正常 clip。

参数在 `args_mixin.py` L410-414（`dynamic_sample` / `max_resample_times` / `overlong_filter`）。

## 4. GSPO / SAPO / CISPO / CHORD / FIPO / REAL 要点

### 4.1 GSPO（Generalized Sample-level Policy Optimization）

**无独立 loss_type**，通过 `importance_sampling_level` 实现：

```python
# grpo_trainer.py L1023-1037
if self.importance_sampling_level == 'token':
    log_importance_weights = log_ratio
elif self.importance_sampling_level in ['sequence', 'sequence_token']:
    seq_level_log_weights = (log_ratio * mask).sum(-1) / mask.sum(-1)   # 序列平均
    if self.importance_sampling_level == 'sequence':
        log_importance_weights = seq_level_log_weights
    else:
        # GSPO-token: sg[si(θ)] * πθ(y)/sg[πθ(y)]
        log_importance_weights = per_token_logps - per_token_logps.detach() + seq_level_log_weights
```

### 4.2 SAPO（L1053-1059）

```text
gate_pos = sigmoid(tau_pos * (coef_1 - 1)) * (4/tau_pos)    # 正 advantage
gate_neg = sigmoid(tau_neg * (coef_1 - 1)) * (4/tau_neg)    # 负 advantage
soft_gate = where(adv > 0, gate_pos, gate_neg)
per_token_loss = -soft_gate * adv
```

### 4.3 CISPO（L1050-1052）

```text
clamped_ratios = clamp(coef_1, max=epsilon_high).detach()
per_token_loss = -clamped_ratios * adv * per_token_logps    # 只裁剪上界
```

### 4.4 CHORD（`swift/rlhf_trainers/utils.py` L1548/L1569）

- `make_chord_sft_dataset`：构造 CHORD 的 SFT 数据迭代器（数据增强：在 response 中插入错误 token）；
- `compute_chord_loss`（L1569）：GRPO loss + SFT loss 混合，利用验证集的隐式偏好（正确解 vs 错误解）；
- 入口：`grpo_trainer.py` `_prepare_chord_dataset`（L2189）+ L1228 叠加。

### 4.5 FIPO（`_compute_fipo_influence` L899）

Future-KL 影响权重：对每个 token 计算未来 KL 的折扣和（`gamma` 衰减），得到 `influence_weight = exp(future_kl)`，乘到 per-token loss 上；含 `dual-clip` 参与掩码与负 advantage 安全掩码（L933-939）。

### 4.6 REAL（L1104-1135）

组内正负样本分离的损失：

```text
neg_loss = log(1 + sum(e^{S_neg/τ}))   # S 为归一化 score
pos_loss = log(1 + sum(e^{-S_pos/τ}))
loss = (neg_loss + pos_loss).mean()
```

## 5. RLSD / SDAR / OPD-RL（自蒸馏 RL 族）

### 5.1 RLSD（`apply_rlsd_reweight`，advantage.py L284）

Self-Distilled RLVR：用 teacher-vs-student log-prob gap 在轨迹**内部**重分配 GRPO advantage：

```text
delta_t = sg(logP_T(y_t) - logP_S(y_t))
w_t = exp(sign(A) * delta_t)
reweight = (1 - lam) + lam * clip(w_t, 1 - clip_range, 1 + clip_range)
A_hat_t = A * sg(reweight)
```

- `lam=0` 退化为纯 GRPO，`lam=1` 全 RLSD；
- `negative_only`：只对负 advantage（错误回答）重加权；
- 参数 `advantage_reweight='rlsd'`（grpo_trainer `_postprocess_batch` L265-281，`_rlsd_effective_lambda` L2171）。

### 5.2 SDAR（`compute_sdar_loss`，advantage.py L352）

置信度门控的教师蒸馏损失：

```text
delta_t = logP_T(y_t) - logP_S(y_t)
g_t = sigmoid(gate_beta * delta_t).detach()      # 门控，无梯度
L_SDAR = agg(g_t * (logP_T(y_t) - logP_S(y_t)))  # 梯度只流学生
loss = policy_loss + sdar_loss_coef * L_SDAR
```

### 5.3 OPD-RL（On-Policy Self-Distillation RL）

- teacher 配置：`_setup_teacher`（rollout_mixin L198），`teacher_kl_coef`（args_mixin L440）；
- advantage 信号：`compute_teacher_logratio`（advantage.py L231），per-token 加到 base advantage 上；
- 监控指标：`compute_teacher_kl_per_token`（L204，k3 估计器）。

## 6. 偏好学习算法（DPO 族）

### 6.1 `DPOTrainer`（`swift/rlhf_trainers/dpo_trainer.py` L49）

继承 `RLHFTrainerMixin, SwiftMixin, DataLoaderMixin, HFDPOTrainer`：

- `concatenated_forward`（L99）：构造 chosen/rejected 拼接前向；
- `compute_ref_log_probs`（L200）：ref 模型算 logp；
- `dpo_loss`（L211）：支持多种变体：
  - `sigmoid`（标准 DPO）、`hinge`、`ipo`、`exo_pair`、`bco_pair`、`sppo_hard`、`nca_pair`、`aot`、`aot_unpaired`、`discopop`、`apo_zero`、`apo_down`、`sft`、`robust`；
- `rpo_alpha`（L383）：叠加 SFT NLL 项（RPO）。

### 6.2 `CPOTrainer`（`cpo_trainer.py` L20）

- 断言无 ref_model；
- `loss_type='simpo'` 时设 `simpo_gamma`（L31）；
- `cpo_alpha` 实现 CPO-SimPO 混合；
- **SimPO 入口**：`rlhf_args.py` L483-489 把 `rlhf_type=='simpo'` 改写为 `cpo` 并设 `loss_type='simpo'`。

### 6.3 `ORPOTrainer`（`orpo_trainer.py` L19）

- 断言无 ref_model（ORPO 参考模型即策略本身）；
- loss = 策略梯度项 + 负对数似然项（odds ratio）。

### 6.4 `KTOTrainer`（`kto_trainer.py` L24）

- `forward`（L50）：按 label 区分 chosen/rejected 并计算 KL_logps；
- `_compute_kl_logps`（L124）：用 ref 模型算 KL；
- `apo_zero_unpaired`（L45）：关闭 KL 项。

### 6.5 `RewardTrainer`（`reward_trainer.py` L28）

- `compute_loss`（L38）：`logsigmoid(rewards_chosen - rewards_rejected - margin)`；
- `center_rewards_coefficient`（L53）：奖励居中正则；
- `visualize_samples`（L74）：打印样本到 wandb。

### 6.6 `PPOTrainer`（`ppo_trainer.py` L23）

- 继承 `SwiftMixin, HFPPOTrainer`；
- `save_model`（L86）只存 policy（`self.model.policy`）；
- value network 来自 HFPPO 的 value_model 参数。

### 6.7 `GKDTrainer`（`gkd_trainer.py` L50）+ `gkd_loss.py`

- `_compute_jsd_loss`（L105）：调用 `gkd_loss`；
- `jsd_loss`（gkd_loss.py L94）：分块 JSD，`beta` 插值 0=forward KL / 1=reverse KL / 之间=JSD；
- `gkd_loss`（L224）：mask → extract_active → jsd 全流程；
- `use_liger_gkd_loss`（L146）：`LigerFusedLinearJSDLoss` 融合算子；
- `sft_alpha`（L244）：叠加 SFT loss；
- `TeacherOutput`（L22）：全词表 / topk 两种 teacher 输出形态。

## 8. 从 reward 到 loss 的完整链路图

```text
completions (response text)
    ↓  compute_rewards_per_func (grpo_algorithm.py L17)
rewards_per_func [N, n_funcs]
    ↓  compute_advantages (advantage.py L10)
advantages [N]  (grpo / rloo / reinforce++)
    ↓  expand_advantage_to_per_token (L253)
advantages [B, T]  (+ OPD-RL teacher 信号)
    ↓  _compute_loss_and_metrics (grpo_trainer.py L948)
policy loss (per loss_type) + beta*KL + sdar + chord ...
    ↓
backward → optimizer.step
```

## 9. 一句话总结

```text
奖励函数打分 → 加权求和 → 组内 advantage 归一化 → per-token 广播 → loss_type 分支裁剪/门控
→ KL 惩罚 + 附加项（SDAR/CHORD/IS）→ backward
```
