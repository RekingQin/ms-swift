## 1. 总体框架

ms-swift 的容错体系分为三层：

```text
第一层：常规 checkpoint（HF Trainer 体系 + SwiftMixin 魔改）
第二层：Flash Checkpoint（dlrover 异步落盘，快速保存）
第三层：分布式后端恢复（DeepSpeed elastic / Megatron / resume_only_model）
```

| 能力 | 位置 | 说明 |
|------|------|------|
| 保存主逻辑 | `swift/trainers/mixin.py` `_save`（L416） | 组合模型/优化器/scheduler/state 保存 |
| Flash 保存 | `_save_flash_checkpoint`（L598） | dlrover 异步 |
| Resume 查找 | `get_resume_checkpoint`（L521） | 读 `dlrover_latest.txt` |
| 恢复目录计算 | `swift/trainers/utils.py` `get_resume_dir`（L367） | 基于版本目录 |
| Megatron 保存 | `swift/megatron/utils/megatron_lm_utils.py` L241/L385 | dist_checkpointing |

## 2. 保存机制

### 2.1 `SwiftMixin._save`（mixin.py L416）

```text
_save(output_dir, state_dict)
  ├─ _save_model (L322)            # 按模型类型分发保存
  │    ├─ SwiftModel → save_pretrained
  │    ├─ PreTrainedModel → save_pretrained
  │    ├─ PeftModel → save_pretrained
  │    └─ flash ckpt → flash_checkpointer.ckpt_agent.save
  ├─ 写 training_args.bin
  ├─ 复制 args.json（模型目录的 args.json）
  ├─ 迁移 predict.jsonl
  └─ save_checkpoint 保存 tokenizer/processor（ModelScope 格式）
```

### 2.2 模型保存分支（`_save_model` L322）

- 兼容 swift + peft；
- `safe_serialization=True` 时用 safetensors；
- 多模态时 patch `auto_model.save_pretrained`，剥离 `0.auto_model.` 前缀；
- **ZeRO-3 修复**：`_fix_zero3_gather_all_parameters`（L568）修复 DeepSpeed ZeRO-3 下 Swift/Peft 附加模块（frozen 参数）保存时被 gather 的问题。

### 2.3 初始模型保存（`_save_initial_model` L224）

- pissa / olora / lora-ga 时额外保存 `initial_model/` 目录（用于权重转换）；
- `_save_converted_model`（L236）：保存转换后的模型到 `converted/`。

### 2.4 checkpoint 目录结构

```text
output_dir/
  ├─ checkpoint-{global_step}/
  │    ├─ model.safetensors        # 模型权重
  │    ├─ optimizer.pt             # 优化器状态
  │    ├─ scheduler.pt             # LR scheduler
  │    ├─ trainer_state.json       # 训练状态（global_step 等）
  │    └─ rng_state_{process_index}.pth   # 各 rank RNG（多机按进程分文件）
  ├─ best_model/ → checkpoint-{best_global_step}   # best 模型软链
  ├─ training_args.bin
  ├─ args.json
  ├─ logging.jsonl
  └─ predict.jsonl
```

## 3. Flash Checkpoint（`_save_flash_checkpoint` L598）

使用 dlrover 的 Flash Checkpointer 做**异步保存**：

```python
# mixin.py L598
HfDdpCheckpointer / HfDeepSpeedCheckpointer   # 按分布式后端选择
保存：model + optimizer + lr_scheduler + RNG state + grad scaler
支持 save_checkpoint_to_storage 异步落盘
```

配套方法：

- `_rotate_flash_checkpoints`（L447）：按 `save_total_limit` 轮换删除旧 checkpoint，正则匹配 `checkpoint-([0-9]+)`；
- `get_last_checkpoint`（L499）/ `_get_last_checkpoint_step`（L513）：读 `dlrover_latest.txt` 拿最后完整 ckpt 的 step；
- `wait_latest_checkpoint`（L560）：等待异步 flash ckpt 落盘完成。

## 4. 恢复机制（Resume）

### 4.1 入口（`swift/pipelines/train/sft.py` L233）

```python
def _get_resume_checkpoint(self, trainer):
    if self.args.resume_from_checkpoint:      # 显式指定
        return self.args.resume_from_checkpoint
    # flash ckpt / elastic 场景自动查找
    return trainer.get_resume_checkpoint()
```

### 4.2 `get_resume_checkpoint`（mixin.py L521）

```text
get_resume_dir(output_dir)            # 基于上一版本目录（utils.py L367）
    + 读 dlrover_latest.txt           # 最新完整 ckpt 的 step
    + 读 trainer_state.json           # 判断 max_steps == step 则返回 None（训练已完成）
```

### 4.3 `resume_only_model` 模式

- `swift/trainers/arguments.py` L161：恢复时**只加载模型权重**，跳过 optimizer/scheduler；
- mixin.py L146-149：`resume_only_model + ignore_data_skip` 时把 `resume_from_checkpoint` 置 None，跳过读取 train_state；
- `_patch_deepspeed_load_checkpoint`（L188）：resume_only_model 时吞掉 deepspeed 加载异常；
- `_load_rng_state`（L277）/ `_load_optimizer_and_scheduler`（L282）：resume_only_model 时跳过加载，支持 ds elastic `load_universal`。

### 4.4 Elastic 恢复（`get_resume_checkpoint_until_find_ucp` L545）

- 通过 `ucp.txt` 追踪 Unicontroller 场景的恢复点（DeepSpeed elastic / 弹性训练）。

## 5. 分布式后端与容错

### 5.1 进程组初始化（`swift/utils/torch_utils.py` L337）

```python
init_process_group():
  NPU → hccl
  CUDA → nccl
  CPU → gloo
```

### 5.2 多机共享盘校验

`check_shared_disk`（torch_utils.py L352）：多机训练校验共享盘，避免各机各存一份。

### 5.3 DDP 保存协调

`safe_ddp_context`（torch_utils.py L92）：DDP 保存/加载时 master/非 master barrier 协调，单机退化为文件锁（`get_cache_dir()/lockers`）。

### 5.4 后端选择

| 后端 | 配置 | 容错要点 |
|------|------|----------|
| DDP | `device_map` 或 NPROC_PER_NODE | 简单，无状态分片 |
| DeepSpeed ZeRO2/3 | `--deepspeed` / `--deepspeed_zero3` | ZeRO3 状态分片，elastic 支持 |
| FSDP/FSDP2 | `--fsdp` | 分片 checkpoint |
| device_map 简易并行 | `--device_map` | 单卡友好 |
| Megatron | `swift/megatron/` | TP/PP/CP/EP 分片 |

### 5.5 Graceful Exit（优雅停机）

`swift/callbacks/deepspeed_elastic.py` `GracefulExitCallback`（L13）：

- `on_step_end`（L23）/ `on_save`（L41）：检测 ShutdownManager 请求；
- all_reduce 传播后**先保存 checkpoint 再优雅停机**，避免训练被打断丢状态。

## 6. Megatron checkpoint（`swift/megatron/`）

### 6.1 保存（`swift/megatron/utils/megatron_lm_utils.py` L241）

```python
save_mcore_checkpoint():
  用 Megatron-Core dist_checkpointing.save 分片保存
  目录 iter_{iteration:07d}/
  latest_checkpointed_iteration.txt 记录最新迭代
  支持 async_sharded_save 异步
```

### 6.2 加载（L385）

```python
load_mcore_checkpoint():
  支持 mcore_model / mcore_adapter 加载
  fp16/bf16 优化器 reload_model_params()
  adapter 过滤
```

### 6.3 HF ↔ Megatron 权重互转（`swift/megatron/convert.py`）

- `convert_hf2mcore`（L32）/ `convert_mcore2hf`（L67）：用 `bridge.load_weights` / `save_weights`；
- MoE 时 `moe_grouped_gemm=True`；
- 按 10GB/线程分片。

### 6.4 NPU/MindSpeed 优化器恢复

`swift/model/npu_patch/megatron_checkpoint.py` L167 `load_optimizer_state_dict()`：修复 NPU 下 optimizer 分布式参数状态加载（`load_parameter_state_from_dp_reshardable` 等）。

## 7. 容错最佳实践清单

| 场景 | 做法 |
|------|------|
| 显式断点续训 | `--resume_from_checkpoint /path/to/checkpoint-xxx` |
| 只恢复模型权重 | `--resume_only_model true` |
| 快速保存大模型 | 开启 Flash Checkpoint（dlrover） |
| 训练被信号打断 | 配 `GracefulExitCallback` + Flash Checkpoint |
| 弹性训练 | DeepSpeed elastic + `get_resume_checkpoint_until_find_ucp` |
| 多机 | 确认共享盘 `check_shared_disk` |
| 保存失败排查 | 看 `dlrover_latest.txt`、`trainer_state.json`、`logging.jsonl` |

---

## 8. 一句话总结

```text
SwiftMixin._save 统一保存（模型+优化器+state）
Flash Checkpoint 异步落盘（dlrover）
get_resume_checkpoint 自动找恢复点（dlrover_latest.txt / trainer_state.json）
resume_only_model 只载权重、跳过 optimizer
Megatron 走 dist_checkpointing 分片
```
