## 1. 设计哲学：三句话

1. **复用 transformers Trainer 体系，深度魔改**：所有训练器都建立在 `HfTrainer` 之上，通过 `SwiftMixin` / `RLHFTrainerMixin` / `RolloutTrainerMixin` 叠加能力，最大程度复用生态与兼容性。
2. **CLI 薄壳 + Pipeline 导演 + Trainer 执行**：命令入口只做分发，流程编排在 Pipeline，重计算在 Trainer/Engine，职责清晰可插拔。
3. **"配置即 dataclass"**：全框架参数统一为 dataclass 多重继承金字塔，扩展新能力 = 继承 + 加字段。

## 4. PT（预训练）模式架构图

PT 是 SFT 的**参数级特化**：`SwiftPretrain` 仅把 `args_class` 换成 `PretrainArguments`，架构与 SFT 完全同构。

```text
┌────────────────────────────── PT 预训练模式 ──────────────────────────────┐
│                                                                           │
│  swift pt --model Qwen3-8B --dataset <纯文本> --truncation_strategy split │
│      │                                                                    │
│      ▼                                                                    │
│  SwiftPretrain (pretrain.py:11, 继承 SwiftSft)                            │
│      │  args_class = PretrainArguments                                    │
│      ▼                                                                    │
│  ┌────────────────── 数据流 ──────────────────┐                            │
│  │ 纯文本数据集 (txt/jsonl)                    │                            │
│  │   → TextGenerationPreprocessor             │                            │
│  │   → template.encode (全 token 作为 labels)  │                            │
│  │   → PackingDataset / LazyLLMDataset        │                            │
│  │   → DataLoaderShard                        │                            │
│  └────────────────────┬───────────────────────┘                            │
│                       ▼                                                    │
│  Seq2SeqTrainer (task_type=causal_lm)                                     │
│    ├─ compute_loss → template.compute_sft_loss (全 token 交叉熵)           │
│    ├─ truncation_strategy='split'  长文档切分                             │
│    └─ backward → optimizer.step                                          │
│                       │                                                   │
│                       ▼                                                   │
│  SwiftMixin._save → checkpoint-{step}                                    │
│                                                                           │
│  特征: 无 system/无模板对话 / 全 token loss / 无 RL 组件 / 单模型          │
└───────────────────────────────────────────────────────────────────────────┘
```

## 10. 架构设计亮点与权衡

| 设计点 | 做法 | 权衡 |
|--------|------|------|
| 复用 HF Trainer | 所有训练器基于 HfTrainer | 兼容生态 vs 被框架约束（靠 patcher 绕过） |
| Mixin 组合 | SwiftMixin / RLHFTrainerMixin / RolloutTrainerMixin | 能力可插拔 vs 多继承复杂 |
| 注册表驱动 | dict + dataclass 元数据 | 扩展简单 vs 全局可变状态 |
| 参数金字塔 | dataclass 多重继承 | 配置统一 vs 字段冲突需小心 |
| on-policy 延迟编码 | RL 样本到 rollout 后才 encode | 灵活 vs 调试不易 |
| 引擎抽象 | BaseInferEngine + 各后端 | 可换后端 vs 接口适配成本 |
| 条件依赖 | 算子库 try/except 降级 | 轻量安装 vs 性能路径不统一 |

