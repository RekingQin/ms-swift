# 00 · 新手代码阅读指南（目录地图 + 阅读路线）

> 返回索引：[README.md](README.md)
> 适用对象：第一次接触 ms-swift 源码、想快速建立全局心智模型并知道"每个目录/文件干啥"的新人。
> 配套深读：本文先给地图与路线，深入原理请按文末"延伸阅读"跳转 01~12 主题文档。

## 1. 先建立一句话心智模型

ms-swift（SWIFT）是魔搭社区提供的大模型与多模态大模型**训练 / 推理 / 评测 / 量化 / 部署**全家桶框架，核心是"训练"：

```text
一条训练命令（swift sft / swift pt / swift rlhf / swift dpo ...）
    ↓
CLI 入口（swift/cli/main.py 分发子命令）
    ↓
Pipeline（swift/pipelines/train/*.py：参数解析 → 模型加载 → 数据准备 → 构造 Trainer）
    ↓
Trainer（swift/trainers/ + swift/rlhf_trainers/：训练循环 / loss 计算 / 保存 checkpoint）
    ↓
Template / Dataset / Dataloader（数据编码与批量）
    ↓
Model / Tuner / Optimizer / Engine（模型适配、轻量微调、分布式后端、推理引擎）
```

记住这条主链，后面所有目录都是围绕它的"零件"：

- **谁来当入口？** → `swift/cli/`
- **流程怎么编排？** → `swift/pipelines/`
- **训练循环在哪？** → `swift/trainers/`（SFT 类）+ `swift/rlhf_trainers/`（RLHF 类）
- **数据长什么样？** → `swift/dataset/` + `swift/dataloader/` + `swift/template/`
- **模型怎么适配？** → `swift/model/`
- **轻量微调怎么实现？** → `swift/tuners/`
- **优化算法在哪里？** → `swift/rl_core/` + `swift/rlhf_trainers/` + `swift/loss/`
- **推理加速怎么接？** → `swift/infer_engine/` + `swift/rollout/`
- **参数都在哪？** → `swift/arguments/`

## 2. 新手阅读原则：不要逐文件硬啃

ms-swift 的代码量很大（`swift/` 下 500+ py 文件，全仓库 1300+ 文件），直接从 `utils/` 或某个底层 engine 开始读，很容易迷路。更推荐按"主链路 + 问题驱动"的方式阅读。

### 2.1 推荐总路线

```text
第 0 站：examples/ 中找一个能跑的脚本（如 examples/train/full/）
    ↓
第 1 站：swift/arguments/ 中的参数类
    理解 ModelArguments / DataArguments / TrainArguments / RLHFArguments
    ↓
第 2 站：swift/pipelines/train/sft.py
    看 SwiftSft.run()，知道一条训练命令做了什么
    ↓
第 3 站：swift/trainers/seq2seq_trainer.py + trainer_factory.py
    看训练器选择与 compute_loss / training_step
    ↓
第 4 站：swift/template/ + swift/dataset/
    理解消息如何被编码成 input_ids / labels
    ↓
第 5 站：swift/model/ + swift/tuners/
    理解模型加载与 LoRA 等轻量微调
    ↓
第 6 站：swift/rlhf_trainers/grpo_trainer.py + swift/rl_core/
    理解 GRPO / DPO 等优化算法（若做 RLHF）
    ↓
第 7 站：swift/infer_engine/ + swift/rollout/
    理解 vLLM / SGLang / LMDeploy 推理加速（若做 RLHF / 推理部署）
```

### 2.2 阅读时重点问 4 个问题

每读一个函数，都建议记录：

```text
1. 输入是什么？dataclass 参数？dict 行？TensorDict？GRPOSample？
2. 输出是什么？会写入哪里（JSONL、wandb、checkpoint）？
3. 在哪个进程执行？单进程还是多卡（torchrun / Megatron / Ray）？
4. 与 transformers 的关系？是复用 HF Trainer 还是自己实现？
```

比如读 `Seq2SeqTrainer.compute_loss` 时，不要只看数学公式，还要问：

```text
谁调用它？（HF Trainer 的 training_step）
传入的是什么？（model_inputs + labels）
它调用了 template 的什么方法？（template.compute_sft_loss）
结果写回哪里？（loss 标量返回给 backward）
```

## 3. 顶层目录功能地图（仓库根）

| 目录/文件 | 用途 | 新手是否要读 |
|-----------|------|--------------|
| `swift/` | **核心源码**，本文重点 | 必读 |
| `examples/` | 各类训练/推理/评测脚本（`*.sh` + 配置），是跑起来的入口 | 强烈建议，先跑通再读码 |
| `tests/` | 单测 + 集成测试（unittest），看用法 / 边界的好材料 | 选读，可当"可运行文档" |
| `docs/` | 官方文档（中英双语，rst/md） | 选读 |
| `scripts/` | 辅助脚本 | 用到再看 |
| `my_docs/` | 本套中文源码解读（你正在看） | 必读 |
| `requirements/` | 依赖清单 | 装环境时看 |
| `asset/` | 图片素材 | 不用看 |

### 3.1 为什么建议先看 `examples/`

`examples/` 会告诉你：

- 用哪个训练入口（`swift sft` / `swift pt` / `swift rlhf` / `swift dpo`...）。
- 用哪个模型、哪个数据集、哪个 template。
- LoRA / 全参 / QLoRA 怎么选。
- 分布式（NPROC_PER_NODE / Megatron / Ray）怎么开。
- 序列并行、梯度累积、学习率等超参怎么设。

阅读 example 的目标不是研究 shell 语法，而是建立这条映射：

```text
脚本参数 / shell 变量
    ↓
swift/arguments/ 中的参数类
    ↓
Pipeline 初始化
    ↓
训练循环中的具体方法调用
```

## 4. `swift/` 核心源码逐目录详解

### 4.1 顶层关键文件

| 文件 | 作用 |
|------|------|
| `swift/cli/main.py` | **命令行总入口**。`ROUTE_MAPPING`（L14-27）把 `sft/pt/rlhf/infer/deploy/...` 映射到各 CLI 模块，`cli_main()`（L86）支持 YAML 参数展开 + `torchrun` 多进程启动。 |
| `swift/__init__.py` | 包初始化，可能包含环境兼容、后端补丁。 |
| `swift/version.py` | 版本号。 |
| `swift/pipelines/__init__.py` | 导出 `sft_main/pretrain_main/rlhf_main/...`。 |

### 4.2 `swift/cli/` —— 命令行薄壳

每个子命令是独立的可执行 `.py` 文件，`if __name__ == '__main__'` 下直接调用 pipeline 的 `xxx_main`：

| CLI 文件 | 调用目标 |
|---------|---------|
| `cli/sft.py` | `swift.pipelines.sft_main()`（含 `try_use_single_device_mode`、`try_init_unsloth`、`try_init_ray`） |
| `cli/pt.py` | `pretrain_main()` |
| `cli/rlhf.py` | `rlhf_main()` |
| `cli/infer.py` | `infer_main()` |
| `cli/deploy.py` | `deploy_main()` |
| `cli/export.py` | `export_main()` |
| `cli/eval.py` | `eval_main()` |
| `cli/merge_lora.py` | `SwiftMergeLoRA().main()` |
| `cli/sample.py` | `sampling_main()` |
| `cli/rollout.py` | `rollout_main()`（RL 场景的 rollout server） |

**注意**：`cli/main.py` 在 `NPROC_PER_NODE`/`NNODES` 环境变量被设置且命令在 `{pt, sft, rlhf, infer}` 中时，会走 `torch.distributed.run` 多进程启动。

### 4.3 `swift/pipelines/` —— 流水线编排层

| 目录/文件 | 作用 |
|-----------|------|
| `pipelines/base.py` | `SwiftPipeline`（L14）抽象基类：`__init__` 做 `_parse_args` + `_set_seed`，`main()`（L49）调用抽象 `run()`。 |
| `pipelines/train/sft.py` | **SFT 主流程** `SwiftSft`（L22）：`run()`（L159）= 数据准备 → `prepare_model`（打适配器）→ `TrainerFactory.get_trainer_cls` → 构造 trainer → `train()`。 |
| `pipelines/train/pretrain.py` | `SwiftPretrain`（L11）继承 `SwiftSft`，仅改参数类 `PretrainArguments`。 |
| `pipelines/train/rlhf.py` | `SwiftRLHF`（L23）继承 `SwiftSft`，额外加载 ref/reward/value/teacher 多模型。 |
| `pipelines/train/kto.py` | KTO 数据预处理（右移构造 KL 项）。 |
| `pipelines/train/tuner.py` | `TunerMixin.prepare_model`（L340）统一打适配器入口。 |
| `pipelines/infer/` | `SwiftInfer`（infer.py L20）、`SwiftDeploy`（deploy.py L28，FastAPI 服务）、`SwiftRolloutDeploy`（rollout.py L724，RL rollout server）。 |
| `pipelines/export/` | `SwiftExport`（export.py L16）：merge_lora / 量化 / mcore 转换。 |
| `pipelines/eval/` | `SwiftEval`（eval.py L18）：以 evalscope 为后端评测。 |
| `pipelines/sampling/` | `SwiftSampling`（sampling.py L18）：离线采样生成。 |

**一句话**：Pipeline 是"流程导演"，它不亲自算，而是把参数、模型、数据、trainer 组装起来并调用 `trainer.train()`。

## 5. 按任务阅读代码：比按目录阅读更有效

### 5.1 我想知道一次 SFT 训练怎么跑

```text
examples/train/full/*.sh
    ↓
swift/cli/sft.py → swift/pipelines/train/sft.py (SwiftSft.run L159)
    ↓
swift/trainers/trainer_factory.py (TrainerFactory.get_trainer_cls)
    ↓
swift/trainers/seq2seq_trainer.py (compute_loss L125 → template.compute_sft_loss)
    ↓
```

## 6. 新手最容易混淆的概念

### 6.1 `Pipeline`、`Trainer`、`Engine` 的区别

```text
Pipeline 是流程导演：组装参数、模型、数据、trainer。
Trainer 是训练循环：HF Trainer 的扩展（SwiftMixin + 各 rlhf trainer）。
Engine 是推理引擎：vLLM / SGLang / LMDeploy / Transformers（infer_engine/）。
```

### 6.2 `SFT`、`PT`、`RLHF` 的区别

| 任务 | 入口 | 说明 |
|------|------|------|
| PT（预训练） | `swift pt` → `SwiftPretrain` | 无监督续训，纯参数层差异。 |
| SFT（指令微调） | `swift sft` → `SwiftSft` | 标准监督微调，任务模板齐全。 |
| RLHF（人类对齐） | `swift rlhf` → `SwiftRLHF` | 多模型（ref/reward/value/teacher）+ rollout 引擎。 |

### 6.3 `LoRA`、`Full`、`GaLore` 的区别

- `--tuner_backend full`：全参微调。
- `--tuner_backend lora`：低秩微调，`swift/tuners/lora.py`。
- GaLore：梯度投影到低秩子空间（`swift/optimizers/galore/`），省优化器显存。

### 6.4 `rlhf_type` 与 `loss_type` 的区别

- `rlhf_type`（dpo/orpo/kto/cpo/rm/ppo/grpo/gkd）决定**用哪个 trainer**。
- `loss_type`（grpo/dapo/bnpo/dr_grpo/fipo/cispo/sapo/real）决定 **GRPO 训练器内的 loss 变体**。

## 7. 新手实操建议路径

1. **先跑起来**：在 `examples/` 找一个 SFT 脚本（小模型 + 单卡），先建立"看得见"的反馈。
2. **打日志 / 断点读 `run()`**：在 `SwiftSft.run()` 各阶段打日志或断点，对照 [01-核心运行流程.md](01-核心运行流程.md)。
3. **顺藤摸瓜**：每遇到一个 `trainer.xxx()`，就去对应 trainer / pipeline 找实现。
4. **算法单独攻**：把 `swift/rlhf_trainers/grpo_trainer.py` 配合 [03-优化算法.md](03-优化算法.md) 单独读。
5. **遇到工具函数再查 `utils/`**：`utils/` 是工具箱，不是主线剧情。
6. **用 tests 当文档**：`tests/train/test_grpo.py` 等单测会告诉你"某个配置应该怎么用"。
